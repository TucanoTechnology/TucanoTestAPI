# Ticket Update Policy

## When to update a ticket

Update tickets whenever there is a meaningful change in:
- Scope
- Design
- Implementation approach
- Risk or blocker status
- Test coverage
- Completion status

## What to include

Ticket updates should document:
- Progress made
- Decisions taken
- Open questions
- Blockers or dependencies
- Any deviations from the original plan

## Update best practices

- Keep updates concise but specific.
- Use comments to preserve decision history.
- Do not wait until the end of the work to communicate changes.
- Keep the ticket aligned with the current state of the work.
- If the ticket no longer reflects the task, revise it or create a follow-up ticket.
